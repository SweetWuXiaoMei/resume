### 1. 全能面试官提示词 —— 一次性生成所有技术面试题

```
你是一位资深技术面试官，正在为一家互联网大厂面试高级/架构师候选人。请根据以下候选人背景，生成一份完整的技术面试题库。

【候选人背景】
- 10年Java开发经验，目前担任技术骨干/架构师角色
- 核心技能：Java并发编程、JVM调优(GC/Crash/OOM排查)、Spring全家桶底层原理、MySQL索引与锁机制、分布式事务/锁/限流熔断、Redis/RocketMQ/ZooKeeper/Dubbo、Arthas/MAT性能诊断
- 项目经验：高并发竞拍系统(Netty+Redis Lua)、短URL服务、GaussDB JDBC驱动开发、支付系统
- 管理过50+微服务集群，30+节点分布式集群

【面试题要求】
1. 覆盖以下领域，每个领域至少3道题，包含基础+深度追问+场景设计三个层次：
   - Java核心：并发编程（AQS/CAS/synchronized锁升级/ThreadLocal内存泄漏）、JVM（CMS/G1/Shenandoah原理、Full GC优化、OOM排查流程）、类加载机制（双亲委派与破坏场景）
   - Spring：Bean生命周期、循环依赖三级缓存、@Transactional失效场景、Spring Cloud组件选型(注册中心/配置中心/网关对比)
   - MySQL：索引优化（覆盖索引/索引下推/MRR）、MVCC与隔离级别实现、死锁排查与预防、主从延迟解决方案
   - 分布式：CAP取舍实践、分布式事务(Seata/TCC/本地消息表)、分布式锁(Redlock争议)、限流算法对比(令牌桶/滑动窗口)
   - 中间件：Redis缓存一致性策略、RocketMQ消息可靠投递(事务消息)、ZooKeeper脑裂、Dubbo服务治理
   - 架构设计：微服务拆分原则、DDD落地经验、灰度发布方案、容量规划与弹性伸缩
2. 至少5道架构设计题，要求候选人画架构图并说明设计取舍
3. 至少3道系统故障排查题，给出故障现象让候选人推断根因
4. 每道题标注难度（初级/中级/高级/专家）和考察目的
5. 末尾附一份面试评估表模板，供面试官打分

请用Markdown表格形式输出题库，表格列：序号 | 领域 | 题目 | 难度 | 考察目的 | 参考答案要点
```

### 2. 深度追问提示词 —— 针对某个回答进行深度追问

```
你是一位资深技术面试官，正在进行架构师岗位的技术面试。候选人对以下问题给出了回答，请针对该回答进行深度追问。

【原问题】：{在此填入你被问到的问题}

【候选人的回答】：{在此填入你的回答}

【深度追问要求】
1. 找出候选人回答中模糊、不准确或可以深挖的点，生成5-8个递进式追问
2. 追问要体现"由浅入深"：从概念确认 → 原理深挖 → 边界case → 生产踩坑经验 → 替代方案对比
3. 如果候选人的回答有错误或遗漏，先设计一个"纠正型追问"引导候选人自行发现
4. 追问要模拟真实面试官的压力测试风格，但不要刻意刁难
5. 对每个追问，给出"面试官期待的满分回答"作为参考答案

【追问格式】
第N层追问：{追问内容}
考察目的：{想考察候选人什么能力}
满分回答要点：{列出关键点}

请开始深度追问。
```

### 3. 模拟面试提示词 —— 进行真实模拟面试

```
你是一位拥有15年经验的技术总监，正在面试一位架构师候选人（10年Java经验）。请进行一场真实的模拟面试，时长约45分钟。

【面试设置】
- 面试阶段：技术二面（Leader/总监面）
- 面试风格：温和但有深度，喜欢从项目经历切入，逐层深入技术细节
- 重点考察领域：架构设计能力、分布式系统经验、故障排查能力、技术选型方法论

【候选人核心项目】（请重点围绕这些项目提问）
1. 高并发竞拍系统：基于Netty+WebSocket长连接，Redis Lua处理出价，QPS峰值10万+，要求出价有序性
2. 短URL系统：日生成量千万级，需要考虑发号器设计、缓存策略、灾备方案
3. GaussDB JDBC驱动：基于PostgreSQL PGJDBC二次开发，兼容GaussDB特有特性(分布式执行计划/JDBC负载均衡)
4. 支付系统：对接多家支付渠道，需要处理分布式事务、对账、幂等

【面试流程】
第一轮：项目深挖（15分钟）
- 请候选人选一个最有成就感的项目，进行深度追问
- 追问角度：架构图 → 技术选型原因 → 核心难点 → 踩过的坑 → 如果重新设计会怎么做

第二轮：技术广度考察（10分钟）
- 穿插4-5个不同领域的问题（JVM/MySQL/Redis/分布式/中间件）
- 要求候选人回答时结合实际生产经验

第三轮：开放设计题（10分钟）
- 现场出一道设计题（如"设计一个秒杀系统/IM系统/配置中心"）
- 观察候选人的架构思维、技术选型逻辑、对非功能需求的考虑

第四轮：行为面试（5分钟）
- 技术决策与团队冲突如何处理
- 如何推动技术演进

第五轮：候选人反问（5分钟）
- 给候选人提供合理的反问机会

【输出格式】
每一轮结束后，给出：
1. 该轮评分（1-10分）
2. 亮点点评
3. 改进建议
4. 追问问题列表

全场结束后，给出：
1. 综合评分与评级（不通过/通过/优秀）
2. 关键优势总结
3. 关键短板与提升建议
4. 针对短板的推荐学习资源

现在开始面试，你先问第一个问题。
```

### 4. 案例分析提示词 —— 生成特定场景的案例分析

```
你是一位资深架构师，请为以下场景生成一个完整的案例分析，用于面试准备。

【案例场景】：{选择场景，如：缓存一致性设计 / 分布式事务选型 / 微服务拆分 / 高并发扣减 / 灰度发布 等}

【案例要求】
1. 给出具体业务背景（让场景真实可信）
2. 列出初始架构方案（可能出现的设计）
3. 分析该方案的潜在问题（至少5个）
4. 提出优化方案（至少3个版本迭代，v1→v2→v3）
5. 每个版本说明：解决了什么问题、引入了什么新问题、是否适合当前阶段
6. 总结"架构设计的本质是取舍"，列出每种方案的核心trade-off

【案例深度要求：三高场景】
- 高并发：QPS 10万+，P99延迟要求 < 100ms
- 高可用：99.99%可用性，同城双活
- 高一致性：涉及资金/库存，不允许超卖/少卖

【输出格式】
## 业务背景
## V1 初始方案
- 架构图描述（文字版/ASCII）
- 方案要点
- 潜在问题（逐条分析）
## V2 优化方案
- 改动点
- 解决的问题
- 引入的新问题
## V3 终极方案
- 核心设计
- Trade-off 分析
## 面试回答框架（STAR法则）
## 常见追问 & 参考答案

请开始案例分析。
```

### 一、面试前的准备工作清单

#### 1.1 硬技能准备（面试前 2-3 周）

| 优先级 | 准备项 | 具体动作 | 验收标准 |
|--------|--------|----------|----------|
| P0 | 项目经历梳理 | 用STAR法则整理3个核心项目（竞拍/支付/短URL），画好架构图 | 能闭眼画出架构图并讲清设计取舍 |
| P0 | Java基础 | 过一遍JVM/并发/集合核心原理，重点关注你简历列出的点 | 面试高频题能对答如流 |
| P0 | 数据库 | 手写10条复杂SQL的执行计划分析，整理常见SQL优化case | 慢查询优化、死锁排查逻辑清晰 |
| P1 | 分布式 | 整理分布式事务/锁/一致性方案的对比表 | 能讲清楚每种方案的适用场景和边界 |
| P1 | 中间件 | Redis/RocketMQ核心原理和常见问题 | 缓存穿透/击穿/雪崩、消息丢失/重复/积压三连问 |
| P2 | 算法题 | 每天刷1-2道中等难度（部分公司架构师也会考） | 至少刷50道中等题 |
| P2 | 系统设计 | 练习3-4个系统设计题（秒杀/IM/短链/Feed流） | 形成自己的设计框架 |

#### 1.2 软实力准备

- **自我介绍**：准备3个版本（30秒电梯演讲 / 2分钟常规版 / 5分钟详细版），反复录音练习
- **你的核心卖点**：提炼3个你最突出的亮点（建议：50+微服务治理+从0到1落地+高并发实战），每个点配1个真实案例
- **离职原因**：准备一段正面积极的回答，绝对不吐槽前公司/前领导
- **反问问题**：准备5-8个有深度的问题（见下文）

#### 1.3 后勤准备（面试前 1 天）

- [ ] 确认面试时间、方式（线上/线下）、面试官数量
- [ ] 线上：测试网络、摄像头、麦克风、屏幕共享；准备有线网络+手机热点的双保险
- [ ] 线下：提前踩点，打印3份简历，带笔记本电脑
- [ ] 着装：商务休闲（线上也要上半身着装得体）
- [ ] 准备纸笔（画架构图用），线上则准备好画图工具（draw.io / Excalidraw）
- [ ] 研究目标公司：业务模式、技术栈、技术博客、面试官背景（LinkedIn）

### 二、常见的架构师面试流程

#### 2.1 典型流程（大厂 4-6 轮）

```
HR 初筛（15min）→ 技术一面（60min）→ 技术二面/Leader面（60min）
                        → 技术三面/总监面（45min）→ 交叉面（45min）→ HR终面（30min）
```

| 面试轮次 | 面试官 | 核心考察点 | 面试风格 | 准备重点 |
|----------|--------|------------|----------|----------|
| HR初筛 | HR | 沟通能力、离职原因、薪资预期 | 温和 | 准备好自我介绍和离职原因 |
| 技术一面 | 资深工程师/TL | 技术深度：Java/JVM/MySQL/中间件原理 | 基础题+深度追问+手写代码 | 硬核基础，别翻车 |
| 技术二面 | Leader/架构师 | 项目经验+架构设计+技术广度 | 从项目切入深挖，穿插技术题 | 讲好你的项目故事 |
| 技术三面 | 总监/CTO | 架构思维、技术视野、团队管理 | 开放设计题+方法论+格局考察 | 展示你的"架构师思维" |
| 交叉面 | 其他部门Leader | 协作能力、技术通用性、潜力 | 风格不定 | 保持稳定发挥 |
| HR终面 | 资深HR/HRD | 文化匹配、职业规划、薪资谈判 | 亲和但有坑 | 提前准备行为面试题 |

#### 2.2 各轮次高频问题

**技术一面（基础深度）**：
- Java：volatile原理（内存屏障）、synchronized锁升级过程、ThreadLocal内存泄漏与FastThreadLocal
- JVM：CMS vs G1 vs ZGC对比、一次Full GC的排查过程、G1的Mixed GC触发条件
- MySQL：为什么用了索引还是很慢、MVCC如何解决幻读、死锁产生条件和MySQL死锁检测机制
- 框架：Spring循环依赖如何解决、@Transactional在什么情况下会失效、BeanFactory和ApplicationContext区别

**技术二面（项目+架构）**：
- "介绍一下你最自豪的项目" → 深挖架构图、技术选型、难点
- "这个项目你觉得最大的败笔是什么" → 考察复盘能力
- "如果重新设计，你会怎么做" → 考察架构演进思维
- "介绍一次线上故障排查经历" → 考察排查能力和SOP
- 现场设计题："设计一个秒杀系统/分布式ID生成器/配置中心"

**总监面（视野+格局）**：
- "你认为一个好的架构师最重要的能力是什么"
- "如何推动一个技术上正确但业务方不理解的决定"
- "介绍一下你的技术成长路径，以及未来3年的规划"
- "你怎么看微服务和服务网格的发展趋势"
- "你怎么做技术选型，有没有踩过坑"

**HR终面（软实力）**：
- 离职原因（高频雷区）
- 期望薪资和薪资结构
- 对你前面几轮面试的自我评价
- 职业规划
- 你最成功的项目和你的角色
- 优缺点自评

### 三、如何用 STAR 法则包装项目经验

#### 3.1 STAR 法则模板

```
S - Situation（背景）：业务场景是什么？当时的痛点？
T - Task（任务）：你的角色是什么？目标是什么？
A - Action（行动）：你具体做了什么？为什么这么做？怎么做决策的？
R - Result（结果）：最终效果如何？有量化数据吗？
```

#### 3.2 包装示例 —— 以高并发竞拍系统为例

**面试官：介绍一下你做过的最有挑战的项目。**

> **S（背景）**：
> 公司主营业务是在线竞拍，原有系统基于Spring MVC+Tomcat，采用数据库行锁处理出价竞拍。随着业务增长，大促期间单品QPS达到8万+，数据库出现严重热点行锁争用，P99延迟爆到3秒以上，高峰期间多次出现出价丢失和排序错乱问题。
>
> **T（任务）**：
> 我作为该项目技术负责人，需要设计一套新的竞拍系统架构，核心目标有三个：
> 1. 支持单品10万+ QPS的出价请求
> 2. 保证出价的严格有序性和公平性（先到先得）
> 3. P99延迟控制在50ms以内
>
> **A（行动）**：
> 我做了以下关键设计决策：
>
> 1. **网络层选型**：放弃HTTP短连接，选用Netty+WebSocket长连接。理由是竞拍场景需要服务器主动推送价格变化和倒计时，WebSocket天然支持全双工通信，Netty的Reactor模型能支撑高并发连接。
>
> 2. **出价引擎核心**：所有出价逻辑下沉到Redis Lua脚本中原子执行。每条出价在Lua中完成"校验余额→检查出价有效性→更新出价榜→扣减冻结金额→发送事件"五个步骤。这里踩过一个坑：初期Lua脚本里用了KEYS命令做模糊匹配，导致Redis阻塞，排查后用Hash结构+精确Key替代。
>
> 3. **出价有序性保证**：利用Redis的Sorted Set作为出价排行榜，score使用"价格+时间戳纳秒"的二段编码。这个设计需要注意一个边界：需要额外维护一个"出价排队顺序"的List来保证同一毫秒内的FIFO，因为Sorted Set的score相同时按字典序排列，不符合先到先得的语义。
>
> 4. **削峰设计**：在Netty层实现了滑动窗口限流器，保证进入Redis层的请求量在其处理能力范围内。同时用本地缓存做了热点数据（起拍价/当前最高价）的秒级缓存，减少Redis调用。
>
> 5. **灾备考虑**：Redis使用AOF+RDB双持久化，同时出价事件异步写入RocketMQ，MySQL做最终落库，即使Redis故障也可以通过MQ中的事件完整恢复状态。
>
> **R（结果）**：
> - 系统上线后，单拍卖品QPS峰值达到12万，P99延迟稳定在30ms以内
> - 大促期间零出价丢失、零排序错乱，系统可用性99.99%
> - Redis CPU使用率从旧方案的80%降到30%
> - 该项目被选为部门年度最佳技术项目

#### 3.3 包装技巧清单

1. **数据一定要量化**：QPS/延迟/可用性/成本，面试官记不住故事但记得住数字
2. **展示决策过程**：不要只说"用了XX技术"，要说"有ABC三种方案，我选了A因为..."，这才体现架构师思维
3. **多讲踩坑**：完美的项目不真实，踩坑+复盘才是好故事
4. **画图加分**：每个项目准备一张架构图，现场画在纸上或共享屏幕
5. **准备失败案例**：面试官很可能会问"最失败的项目/决策"，提前准备好并说明你学到了什么

### 四、"没有架构师 title 但做过架构师的事"的回答策略

#### 4.1 核心逻辑

很多候选人的困境：实际干了架构师的活（技术选型、系统设计、推动落地、带人），但名片上写的是"高级开发工程师"或"技术专家"。

**面试官问这个问题的潜台词**："你没有架构师头衔，凭什么来面架构师？"

**你的回答策略**：不辩解，用事实证明。

#### 4.2 回答模板

> "确实，我之前的正式title不是架构师，但实际工作内容就是架构师的职责。我判断一个人是不是架构师，不看头衔看三点：**有没有做过技术选型和架构设计、有没有推动过技术演进落地、有没有影响过团队的技术决策**。
>
> 在这三个方面，我的经历包括：
>
> **技术选型和架构设计**：我主导了竞拍系统从0到1的架构设计，从网络层选型（Netty vs Vert.x vs 原生NIO），到核心引擎方案（Redis Lua vs 纯Java + 锁 vs Raft共识），再到容灾方案的设计，都是我在调研和推动的。
>
> **技术演进落地**：我推动了我们微服务体系的标准化，从Spring Cloud版本选型、服务拆分规范、API兼容性管理、到灰度发布流程，形成了一套可复制的落地方法论，最终管理了50+微服务。
>
> **影响团队技术决策**：我组织了每周的代码评审和技术分享，推动了Clean Code规范和设计模式在团队的落地。
>
> 所以虽然名片上写的不是架构师，但我做的事情和架构师没有本质区别。面试架构师岗位，我认为我的经历是完全匹配的。"

#### 4.3 要点提醒

- **不要**说"我们公司不给升title"——这是在抱怨，面试官会觉得你负能量
- **不要**自称架构师但拿不出架构设计案例——会被一问就穿帮
- **要**强调"做的事情"而非"title"，用具体案例支撑
- **要**展示架构师的核心能力：trade-off思维、技术前瞻性、推动力

### 五、面试中的加分技巧和减分行为

#### 5.1 加分技巧

| 技巧 | 具体做法 | 为什么加分 |
|------|----------|------------|
| 画图讲架构 | 面试官问架构题时，主动说"我画个图"，在纸上/白板/共享屏幕上画 | 展示结构化的架构思维，是架构师的底层能力 |
| 讲Trade-off | 任何技术选型都讲"我选了方案A因为XX，放弃了方案B的YY优势，做了ZZ补偿" | 面试官想看到的是决策逻辑，不是正确答案 |
| 主动提踩坑 | 讲项目时主动说"这里踩过一个坑"，说明现象、根因、解决方案、复盘 | 有经验的架构师一定踩过很多坑，讲得出来才是真经验 |
| 展示数据敏感性 | 回答性能相关问题时，带出具体的数字和指标 | 证明你做过真正的性能优化，不是纸上谈兵 |
| 追问时要体系化 | 被追问时，用"这个问题涉及三个层面：原理层面、实践层面、前沿层面"开头 | 展示你的知识是体系化的，不是零散的 |
| 坦诚不会的 | 被问到不会的，说"这个我没深入研究过，但据我理解...我的学习思路是..." | 比不懂装懂强100倍 |
| 好反问 | 反问面试官有深度的问题 | 展示你的思考层次 |

**高水平的反问问题清单**：
1. "团队目前的架构演进方向是什么？有哪些技术债务正在解决？"
2. "团队的技术决策机制是怎样的？架构师在其中有怎样的自主权？"
3. "这个岗位期待候选人在入职3个月/6个月/1年分别达成什么目标？"
4. "团队目前最大的技术挑战是什么？"
5. "公司的技术分享和成长文化是怎样的？"

#### 5.2 减分行为（红线）

| 减分行为 | 为什么减分 | 正确做法 |
|----------|------------|----------|
| 不懂装懂 | 面试官稍微追问就会穿帮，直接出局 | 坦诚不足 + 展示学习思路 |
| 吐槽前公司/前Leader | 面试官会觉得你难管理、负能量 | 从正面角度讲离职原因，如"希望挑战更大规模系统" |
| 只讲用了什么技术，不讲为什么 | 那是开发思维，不是架构师思维 | 每次都讲"为什么选择"和"怎么决策的" |
| 过于激进地否定现有方案 | 面试官可能就是那个方案的设计者 | 先肯定方案合理性，再提出"可以考虑的优化方向" |
| 项目讲得太笼统 | "我负责整个后端开发"——等于没说 | 用STAR法则，精确到你的具体贡献 |
| 机械背诵概念 | 一听就是在背八股文 | 用自己的话讲，配真实案例 |
| 回答问题过于简略 | 面试不是考试答卷 | 每个回答控制在2-5分钟，有结构、有深度、有案例 |
| 薪资过早暴露底线 | 会被压价 | 先反问薪资结构和范围 |
| 说自己"没有短板" | 不真实，面试官会觉得你不自省 | 真诚说1-2个短板 + 你的改进动作 |
| 拒绝面试官的引导 | 面试官追问是为了帮你展开 | 顺着面试官的思路走，不要对抗 |

### 六、薪资谈判技巧

#### 6.1 谈判核心原则

1. **先报价者输**：尽量让HR先给出范围或预算
2. **永远不要只说一个数字**：报一个范围，底部是你愿意接受的最低值
3. **总包比月薪重要**：问清楚薪资结构——Base/年终/股票/期权/补贴/公积金比例
4. **有备选方案**：最好手上有其他offer或面试中，这是最强筹码
5. **薪资不是唯一维度**：成长空间、职级、团队、技术栈匹配度也要纳入考量

#### 6.2 薪资谈判话术模板

**场景一：HR问"你的期望薪资是多少？"（初面）**

> "我对薪资持开放态度，想先全面了解岗位职级和团队情况。方便了解一下这个岗位的薪资结构和预算区间吗？"

**场景二：HR坚持先报价**

> "我了解市场行情和自身能力，期望年薪总包在XX万-YY万之间（底线到期望），当然这个数字会根据年终发放方式、股票/期权方案以及其他福利做调整。"

**场景三：HR反馈"你的期望偏高"**

> "理解。方便告知具体的budget区间吗？我可以结合整体package再评估。另外，除了Base部分，我也想了解一下年终奖、股票/期权、社保公积金的具体政策。"

**场景四：拿到offer但想争取更高**

> "感谢认可！我对这个机会非常感兴趣。不过目前手上还有另一个offer在考虑。如果能将Base调整到XX，我可以马上确定，这也能体现公司对技术人才的价值认可。"

#### 6.3 薪资谈判前必须搞清楚的信息

- [ ] 薪资结构：Base x N个月 + 年终奖（平均值和浮动范围）+ 股票/期权（行权周期和归属方式）+ 补贴（餐补/交通/住房）
- [ ] 公积金：缴纳比例（5% vs 12%影响很大）和基数
- [ ] 试用期：时长和薪资比例（一般100%）
- [ ] 涨薪和晋升：年度调薪窗口、晋升周期和涨幅
- [ ] 竞业和保密：竞业范围是否合理
- [ ] 目标公司和岗位的职级体系（P6/P7/P8对应什么层级和薪资范围）

#### 6.4 架构师薪资谈判的独特筹码

架构师面试，你可以强调以下价值点：

1. **建设性价值 vs 执行性价值**：你不是来写代码的，是来解决架构问题、避免技术决策失误的——一次错误的技术选型可能让公司浪费数百万
2. **技术影响力**：你的架构方案会决定整个团队未来几年的技术走向
3. **从0到1的落地能力**：不止是设计，还包括推动落地、推动团队的技术成长
4. **生产级经验**：你经历过50+微服务的治理、高并发场景的考验，这是书本上学不到的
